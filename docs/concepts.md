## 图像如何进入模型

图像生成模型通常不直接处理完整像素，而是先由 VAE 压缩到 **latent** 表示。文本编码器把提示词转换为条件特征，denoiser 在这些条件下预测生成过程中的方向。最终，VAE 将生成的 latent 解码回图片。

这三个组件承担不同职责：更换 denoiser 并不意味着任意 VAE 或文本编码器都能配套使用。不同家族的 latent 通道数、归一化、文本特征和条件布局不同，因此资产必须按家族与变体准备。

## 流匹配在学习什么

对常见的 noise-minus-data 约定，可将训练过程写为：

```text
z₀ = encode(image)
ε  = Gaussian noise
zσ = (1 − σ) · z₀ + σ · ε
v* = ε − z₀
loss = mean((model(zσ, time(σ), text) − v*)²)
```

`σ` 表示噪声比例。训练不断采样不同图片、噪声与时间，学习从噪声向数据移动的方向；生成时，采样器沿多个时间步逐步还原图像。

这是理解流程的示意公式。各模型的时间单位、移位时间表、预测符号及条件细节由原生实现负责，例如 Z-Image 的符号在模型边界转换。不能将某个家族的整数 timestep 当成所有模型共用的噪声比例。

## LoRA 和 full 改变什么

LoRA 冻结原始权重 `W`，训练低秩分支：

```text
W_effective = W + (alpha / rank) · B · A
```

`rank` 决定低秩分解的中间维度，`alpha/rank` 决定增量缩放。更高的 rank 增加适配器容量，也增加参数、梯度和优化器状态；效果仍需通过数据与预览判断。冻结底模省去了它的参数梯度和优化器状态，但反向传播仍需经过底模计算输入梯度，因此 LoRA 训练仍会使用大量显存。

LoHa、LoKr 使用其他结构表达权重增量，可通过 `train.adapter.algorithm` 选择。Full 则直接更新选中的 denoiser 参数，不使用适配器分支。它通常需要更多训练状态，并输出完整模型。

这些选择只决定“更新谁”。相同的适配器方式可以用于流匹配或图像修复，具体目标由 `method.kind` 决定。

## 为什么先生成缓存

常规图像流匹配不更新 VAE 和文本编码器，提前生成 latent、文本特征和条件，可以避免每次训练重新编码。于是工作分为：

1. `validate` 检查配置字段与支持组合。
2. `cache` 读取媒体和编码组件，生成训练表示。
3. `train` 读取缓存和 denoiser，执行梯度更新。

缓存与实际输入绑定。修改图片、提示词、参考图、模型编码资产或裁剪规则后，需要重新生成。单纯调整学习率或训练步数不改变编码输入。

图像修复需要训练中的 LQ 编码器和像素级监督，因此仍会读取 LQ/HQ 图片；不能把它理解为完全离线的 latent 训练。训练预览也需要编码提示词并解码结果，应保留对应 VAE 和文本资产。

## 一步修复与生成训练的区别

修复从真实的低质量图像出发：`LQ → 编码 → 固定时间预测 → 解码 → 与 HQ 比较`。LQ latent 直接输入，不再额外加高斯噪声。对于 noise-minus-data 模型，恢复近似为 `z_clean = z_lq − σ · velocity`。

这里的 `σ` 决定一步恢复的时间位置，校准会根据数据选择它；encoder adapter 帮助 LQ 表示接近适合恢复的 latent 分布。像素损失、感知损失与 LRR 分别约束输出和表示。完整数据与配置见[修复教程](restoration-tutorial.md)。

## 更新次数如何计算

`max_updates` 统计优化器更新，`accumulation_steps` 统计一次更新前累积多少个 microbatch。例如单设备下：

```text
batch_size = 2
accumulation_steps = 4
每次更新累计处理 2 × 4 = 8 个样本
max_updates = 1000 → 累计处理 8000 个样本（包含重复取样）
```

梯度累积可以增加一次更新聚合的样本数，而无需同时放入更大的 microbatch。它不会消除单个样本的激活开销，速度和数值也不保证与同等大小的直接 batch 完全一致。学习率预热、保存周期和预览周期都以更新次数为单位。

## 显存策略改变什么

重算用额外前向计算换取较少的激活保存；卸载将部分权重或激活放到主机内存；BF16 AMP 降低部分前向运算的计算精度。它们解决不同来源的内存占用，选择依据应是实际瓶颈。

这些选项不重新定义训练目的，但会影响执行耗时和浮点计算，所以部分设置属于续训身份。不要把“只改显存策略”理解为一定可以沿用同一 checkpoint 得到相同数值轨迹。操作建议见[执行策略](training/execution.md)。

权重量化减少冻结基模的存储与传输量：浮点源文件可在训练前按层送到 GPU 量化，也可提前转换成可复用文件。计算时只临时展开当前层权重，并用浮点输入完成前向和输入梯度；这会增加反量化开销，当前层的浮点显存仍不可省。量化只用于冻结基模的适配器训练，Full 要求浮点权重。详见[量化基模训练](training/quantized-base.md)。

## 模型文件与训练状态

发布文件保存推理所需的模型或适配器；checkpoint 还需保存优化器、随机状态和数据位置。只有后者能恢复中断的优化过程。

图像修复还可能发布 encoder adapter，并将有效 sigma 写入模型产物。推理应加载同一轮训练对应的 denoiser 与 encoder，保持时间参数一致。具体加载方法见[推理与模型使用](inference.md)。
